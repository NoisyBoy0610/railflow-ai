## 1. SYSTEM IDENTITY, MISSION & GUARDRAILS (`system.md`)

### 1.1 System Mission
RailFlow AI is a unified, accessible, zero-friction railway passenger operating system designed to replace legacy IRCTC bottlenecks with 10 integrated agentic subsystems powered by OpenAI models (GPT-4o / GPT-4o-mini) and an offline-first synthetic Passenger Reservation System (PRS) engine.

### 1.2 Mandatory Hackathon Guardrails
- **Zero Live Government / CRIS / IRCTC API Calls:** Never make real outbound calls to official Indian Railways servers or sensitive endpoints.
- **Strict Synthetic & Deterministic Data:** All trains, PNRs, stations, fares, quotas, charts, and delay events must be generated locally using deterministic mock engines.
- **No Real PII / Financial Data:** Use mock Indian identities, synthetic PNR records (e.g., `821-4928103`), and sandboxed payment confirmation tokens.
- **OpenAI Integration:** OpenAI structured outputs (`json_object` or function calling) must directly power conversational intent mapping, refund policy deduction logic, quota explainers, and multimodal image severity triage.
- **Network Resilience:** Target bundle size < 1.5 MB with full offline/low-bandwidth progressive support for Tier-2/3 connectivity.

### 1.3 Target Tech Stack
- **Framework:** Next.js 14+ (App Router), TypeScript, React 18+
- **Styling & UI:** TailwindCSS, Lucide-React icons, Shadcn/UI primitives, Framer Motion
- **State & Storage:** Zustand / Dexie.js (IndexedDB) / SQLite in-memory mock store
- **AI Client:** Official `openai` SDK (`gpt-4o` and `gpt-4o-mini`)
- **Speech Interface:** Web Speech API (SpeechRecognition & SpeechSynthesis) with Indic fallbacks

## 2. THE 10 INTEGRATED SUBSYSTEMS SPECIFICATION

### Subsystem 1: AI TDR & Auto-Refund Dispute Engine
- **Input:** PNR number + passenger issue statement (e.g., *"Train delayed by 3.5 hours at SBC, didn't travel"* or *"AC coach cooling failed throughout the night"*).
- **Logic:** Matches input against synthetic train delay logs and official IRCTC TDR refund clauses (Rule 14.1 through Rule 14.22).
- **Output:** Exact eligible rule clause, step-by-step net refund breakdown (Base Fare - Clerkage/GST), and 1-click filing confirmation.

### Subsystem 2: Indic Multimodal Voice-First Booking
- **Input:** Conversational voice/text in 10 Indian languages (Hindi, Kannada, Tamil, Telugu, Bengali, Marathi, Gujarati, Malayalam, Odia, English).
- **Logic:** OpenAI parses unstructured language into a strict JSON payload: `{ source, destination, date, class, passengerCount, quotaPreference }`.
- **Output:** Auto-populates search query and voice-reads options back in the selected Indic language.

### Subsystem 3: Smart Multi-Leg & Break-Journey Routing Optimizer
- **Input:** Origin & Destination stations where direct trains show `REGRET` or high `WL`.
- **Logic:** Graph pathfinding algorithm (Dijkstra / A*) identifying safe split-seat combinations:
  - *Option A:* Same train, different seats across intermediate junction.
  - *Option B:* Two fast trains via major junction with a guaranteed 45-120 min layover buffer.
- **Output:** Comparative card displaying direct WL vs. 100% confirmed multi-leg route.

### Subsystem 4: Zero-Friction & Anti-Dark-Pattern Booking UI
- **Logic:** Instant session preservation (no 5-minute timeout drops), zero visual CAPTCHAs (replaced with invisible client-side challenge), explicit unbundled opt-in for insurance, and full transparent base fare vs. dynamic pricing breakdown.

### Subsystem 5: Explainable Quota & Waitlist (WL/RAC) Predictor
- **Input:** PNR or train search availability showing cryptic codes (`GNWL 42`, `RLWL 5`, `PQWL 18`, `RAC 12`).
- **Logic:** OpenAI explains the quota hierarchy, why specific waitlists move slower, calculates deterministic confirmation % based on historical patterns, and suggests alternatives.

### Subsystem 6: Senior Citizen & Family Berth Proximity Allocator
- **Logic:** Analyzes passenger age/gender matrix before submission. Automatically maps senior citizens (M60+, F45+) and pregnant passengers to Lower Berth / Senior Quota (`SS`) while co-locating family members in the same coach compartment.

### Subsystem 7: Tatkal Rush Rapid-Form Pre-Flight Sandbox
- **Logic:** Local offline pre-flight builder. Pre-saves verified master passenger details, pre-authorizes synthetic payment intent, and runs a sub-10-second booking simulation when the 10:00/11:00 AM window opens.

### Subsystem 8: Dynamic Disruption & Rescheduling Copilot
- **Logic:** Monitors simulated live train delays. When delays exceed 3 hours or routes divert, the copilot proactively pops up:
  1. Free rescheduling / 1-tap full refund TDR.
  2. Alternative train recommendations passing through the same corridor.
  3. Single-tap booking for station retiring rooms.

### Subsystem 9: Single-Window Station Accessibility & Last-Mile Concierge
- **Logic:** Unified single-window interface to book verified station porters (Coolie tariff matrix), battery-operated transit cars for elderly passengers, wheelchair assistance, and seat-delivered IRCTC e-catering.

### Subsystem 10: Multimodal RailMadad Grievance Engine (Vision AI)
- **Input:** Photo of issue (dirty toilet, broken berth, AC leak, unhygienic pantry food) + PNR.
- **Logic:** GPT-4o Vision classifies image severity (Critical / High / Normal), extracts coach details, maps to correct division department, and generates a structured grievance token.
